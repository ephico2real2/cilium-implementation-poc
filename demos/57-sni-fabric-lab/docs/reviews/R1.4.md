## The two designs, and what was taken

Both designs agree on the structure: the instrumentations named in `requirements.txt` (never
`opentelemetry-bootstrap`), each `CMD` started by `opentelemetry-instrument`, traces only (metrics
and logs belong to R1.8 and R1.7), OTLP/HTTP to Envoy's `otlp.mesh`, W3C trace context, every
trace kept, `/metrics`, `/healthz` and `/readyz` not traced, and a phase 6 check that places one
order with its own `traceparent` and reads that exact trace from Tempo.

| Point | Codex | OB1-lite | Taken, and why |
|---|---|---|---|
| Base | design and diffs | design, diffs and a tested patch for all 19 files | OB1-lite's patch: it was already checked against the lab-free tests and in throwaway containers |
| OTLP protocol variable | `OTEL_EXPORTER_OTLP_TRACES_PROTOCOL` | `OTEL_EXPORTER_OTLP_PROTOCOL` | OB1-lite's: measured that the distro defaults to gRPC and sends nothing without it |
| `service.version` | `1.0.0`, the API's declared version | `dev`, the images' tag | `dev`: it is the version of what runs, and R5 versions the images and this together |
| httpx exclusions | Envoy `/ready`, `/healthz`, `/metrics/worker` | none | none: orders-api makes those calls only when the admin portal's status page is opened (`app/main.py:282-287`), so they belong to that request's trace |
| The phase 6 check | one check, resources included | three checks: instrumented processes, the order's span tree, resources | OB1-lite's: tcp-svc sends no span, so only its process environment can prove AC 1 |
| Lock recipe | pinned pip and pip-tools, fresh resolve | pip-tools 7.6.2 over the existing locks, measured byte-identical | OB1-lite's; the orchestrator re-ran it and got the same three files byte for byte |
