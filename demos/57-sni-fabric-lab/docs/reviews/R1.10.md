# Review record: R1.10, VictoriaMetrics' own UI from the Mac

Built by the orchestrator, 2026-10-22, on the operator's decision: "we need to expose the full
Victoria metrics ui so that we can see it as a full functioning app. We dont need to block any
path." Reviewed by Codex and OB1-lite, neither of whom wrote it.

| What | Measurement |
|---|---|

## The change

| Where | What |
|---|---|
| `envoy/envoy.yaml`, ops_http | `victoriametrics.fabric.localtest.me`: every path to VictoriaMetrics, as `prometheus.fabric.localtest.me` does for Prometheus; GET retried as the read API's GET was (`*idempotent_retry`), any other method only when it never reached the store (`*safe_retry`) |
| `envoy/envoy.yaml`, mesh_http | unchanged: on `victoriametrics.mesh`, only the two write paths, the read API and `/health` |
| `tests/r1-2/test_store_routes.sh` | the five host refusals become ten host checks that change no data: the root page and vmui by their text, vmui's script bundle by the name the page gives it, the status, flags, metrics and snapshot-list pages, a GET on `delete_series` (the store's own 405) and an empty import (204) |
| `tests/vmui_capture.py` | vmui in Chromium, light and dark: a query of the shop's traffic per Envoy upstream, and the cardinality explorer; no page error, no response of 400 or more, each page's expected text |
| Docs | usage, the remote-write page (with both screenshots), run.sh's login table, the edge and north-south figures, the CI header |
